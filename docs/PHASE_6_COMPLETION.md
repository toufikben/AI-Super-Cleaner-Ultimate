# Phase 6 Completion Record

## Scope

تم تنفيذ مسار التنظيف الآمن وإدارة Trash والاستعادة والحذف الدائم.

## Delivered

أضيف جدول `trash_items` إلى Room مع Migration من الإصدار 2 إلى الإصدار 3. يسجل الجدول URI واسم العرض والحجم ووقت النقل إلى السلة، ولا ينسخ الملفات الضخمة بلا ضرورة.

أضيف `CleanupManager` لاستخدام MediaStore recoverable trash على Android 10 وما بعده عبر `IS_TRASHED` و`DATE_EXPIRES`. عند نجاح النقل يسجل العنصر محلياً في Trash. على الإصدارات الأقدم التي لا توفر recoverable trash لا يحذف التطبيق الملف، بل يعيد رسالة واضحة بأن العملية غير متاحة بأمان.

أصبح تبويب Clean يعرض الملفات التي تحتوي على content hash للمراجعة. يستطيع المستخدم تحديد الملفات يدوياً، ويرى العدد والحجم، ثم يضغط Move selected to Trash. قبل النقل يظهر حوار تأكيد يتضمن العدد والحجم ويوضح أن العملية قابلة للاستعادة حيث يدعم Android ذلك.

أصبح تبويب Tools يعرض Trash. يستطيع المستخدم Restore مباشرة، أو اختيار Delete permanently. الحذف الدائم محمي بحوار تأكيد مستقل يوضح أن الإجراء لا يمكن التراجع عنه.

## Acceptance

- `assembleDebug` و`lintDebug` نجحا.
- لا يحدث حذف دون اختيار المستخدم وتأكيده.
- لا يظهر إعلان قبل تأكيد الحذف.
- يستخدم التطبيق MediaStore recoverable trash على الإصدارات المدعومة.
- لا تُنسخ الملفات الكبيرة إلى مجلد موازٍ بلا ضرورة.
- Restore متاح من Trash.
- Permanent Delete منفصل ومؤكد بوضوح.
- فشل الملف أو عدم توفر API يعرض رسالة ولا يؤدي إلى فقد صامت.

## Limitation

على Android الأقدم من API 29 لا يوفر التطبيق Trash قابلة للاستعادة، ولذلك يمنع مسار النقل الآمن بدلاً من تنفيذ حذف غير قابل للتراجع. تحتاج بعض تدفقات MediaStore إلى تأكيد نظام رسمي على إصدارات Android أو مزودي محتوى محددين، وسيتم توسيع معالجة IntentSender عند اختبار الأجهزة الفعلية.
